# Phase 5 Plan: i18n EN/TH + check:i18n

**Goal:** EN/TH toggle swaps ALL visible UI text; `npm run check:i18n` exits non-zero when any key exists in one language but not the other (both directions).

## Decisions applied
- D9: plain JSON dictionaries `web/src/i18n/en.json`, `th.json` + tiny hook (no react-i18next, no ICU/plural). Flat-or-nested keys are flattened for comparison.
- AGENTS: user-facing errors go through i18n → `mapFirebaseError` must return a key (+ params) or take `t`, not hardcoded English. Same for `validateTiktokUrl` message.
- Cut order: full i18n is cuttable, but the check script + toggle are R5 and stay.

## Tasks
1. **check script (tests first)** `scripts/check-i18n.ts` + pure `scripts/lib/i18n.ts` (`flattenKeys`, `diffKeys(en, th) → {missingInTh[], missingInEn[]}`); unit tests for both directions; `npm run check:i18n` prints missing keys with language and exits 1.
2. **Dictionaries + hook** `web/src/i18n/` — `I18nProvider`, `useT()`, `lang` state persisted in `localStorage`, default EN, `t(key, params?)` with `{name}` interpolation; fallback shows the key (never blank).
3. **Extract strings** from `App.tsx` (login, creator, ops, export, modal, badges/status labels), `validation.ts`, `errorMapping.ts` into keys; Thai translations (flag machine-quality TH for native review in NOTES).
4. **Toggle** EN/TH button in header.
5. **Evidence** — (a) `npm run check:i18n` green; (b) delete one key from `th.json` → exit 1 naming the key, restore; (c) add key only to `th.json` → exit 1 (reverse direction), restore; (d) manual: toggle swaps all screens; add `check:i18n` to `npm test`; STATE F5.

## Risks
- Existing tests assert English substrings of `mapFirebaseError`/validation → update tests to assert keys.
- Dates/status values from Firestore stay raw; only labels translated.
- Thai text in dictionaries must be UTF-8; confirm no mojibake in terminal and browser.

## Done when
- [ ] R5.1 + R5.2 evidenced incl. both deliberate-failure runs  - [ ] no hardcoded user-facing English left in `web/src` (grep check)  - [ ] user answers 3 "what if" questions first
